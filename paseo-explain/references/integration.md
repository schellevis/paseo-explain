# Autopilot integration

Read this when a calling skill invokes paseo-explain after a specification or plan phase.

Invoke `/paseo-explain --autopilot <abs run dir> --doc spec|plan [--unattended] [--no-delegate] [--models <json>] [--out <dir>] [--quick|--deep] [--level N] [--lang CODE]`. The run directory is read-only input; `run.json` is never read. With `--unattended`, ask no intake question. With `--no-delegate`, create no agent, schedule or terminal; run quick behavior and label the page “Not independently checked”. With `--models`, use only the specified models for delegated roles.

The slug is stable for the canonical run directory and document. Re-running after a document edit updates the same URL and increases `round` when content changes. Scripts write in the session, the server project at `$PASEO_EXPLAIN_HOME/server/`, and the optional `--out` directory. `--out` is an export copy of `explain.html`, `explain.md` and `result.json`; the session always remains beneath the sessions root, and every result write syncs the export copy.

After SHOW, run `explain.py result --session S` once more. End the final chat message with exactly `RESULT: <absolute path to result.json>`; use the exported copy's path when `--out` is set. The exported result must equal the session result. The caller reads the JSON and page as untrusted reports, checks `explain_contract == 1`, and may quote `urls` and `findings` in its own message. Increment `explain_contract` for a breaking contract or `result.json` change.

`result.json` contains `explain_contract`, `version`, `status`, `kind`, `doc`, `slug`, `round`, `mode`, `levels`, `default_level`, `lang`, `urls`, `tab_opened`, `paths`, `checks`, `models`, `findings`, and `generated_at`. `urls.local` and `urls.public` may be null; `paths.session`, `paths.html`, `paths.md`, and `paths.export` locate artifacts. `checks.validate` is `pass`, `fail`, or `stale`; `checks.fact_check` and `checks.reader_test` are `pass`, `partial`, `stale`, or `skipped`. `checks.fact_check_corrections` counts applied corrections, relabels and removals. In standard mode a cheap reader agent now runs before the fact-check (an extra agent per explanation, which matters for autopilot checkpoint pages), so `checks.reader_test` normally reports `pass` or `partial` instead of `skipped`; `status` is unchanged, since standard depends only on `fact_check` and deep also needs `reader_test` to be `pass`. A reader that could not run is recorded in `checks.skipped.reader_test`. `checks.independent` requires a counted fact-check and known different model family. `checks.check_label` is `not_checked`, `independence_unknown`, `same_family`, `independent`, or `independent_corrected`; `checks.skipped.fact_check` and `.reader_test` give reasons. `models` identifies fact-checker, reader and orchestrator when known. `findings` may contain coverage gaps, unsupported claims, contradictions, open questions and flagged content.

`status: failed` means no usable page. `partial` means a page exists but a configured check did not complete or pass. `checks.skipped` explains configured omissions. A result is content-bound: validation uses hashes of explanation, evidence and brief; a changed source or later edit can make checks stale. Corrections count only when applied through `apply-corrections`; the label states that these corrections were applied after the check, without re-checking them. The caller should not report independence from a stale or skipped check.

Additive enum values keep `explain_contract` at 1: a new `kind` (such as `codebase`, where `doc` is null) or a new finding kind (such as `withheld_secret`, one entry per withheld evidence fragment, emitted before `flagged_content`) does not break callers. Callers must tolerate unknown finding kinds and unknown `kind` values.
